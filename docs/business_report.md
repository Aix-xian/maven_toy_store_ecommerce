# 玩具电商经营分析：业务报告与实施过程

报告日期：2026-11-02。数据来源：Maven Analytics 的 Maven Fuzzy Factory 公开模拟电商数据。技术路线：MySQL + Python + Excel。分析计算在 WSL 完成，项目文件整理为可在 Windows 查看、适合 GitHub 展示的仓库。

本项目从六张业务表出发，完成数据导入、质量检查、月度经营、渠道设备、购买漏斗、商品退款分析及 Excel 展示。本报告重点说明每一步为什么做、如何处理、验证了什么，以及具体生成了哪些文件。所有文件路径均相对项目根目录。

## 1. 项目目标与数据范围

项目围绕五个经营问题展开：销售额如何变化；哪些渠道贡献增长；移动与桌面的转化差异出现在哪些阶段；客单价变化与商品组合有什么关系；如何在相同观察时长下比较退款。

数据链路为“网站会话—页面浏览—订单—订单商品—退款”，商品表提供商品名称与上市时间。一笔会话可能关联多笔订单，一笔订单包含多条商品明细，同一明细可能发生多次部分退款。分析时先确定粒度，再关联和汇总，避免重复计算。

| 业务表 | 一行代表什么 | 导入行数 |
| --- | --- | ---: |
| website_sessions | 一次网站会话 | 472,871 |
| website_pageviews | 一次页面浏览 | 1,188,124 |
| orders | 一笔订单 | 32,313 |
| order_items | 一条订单商品明细 | 40,025 |
| order_item_refunds | 一笔商品明细退款事件 | 1,731 |
| products | 一种商品 | 4 |

六表合计导入 1,735,068 行；这个数字合计了不同业务粒度，不能解释成用户数或订单数。数据没有 users 表，不能据此分析用户人口属性，也不为 user_id 建立不存在的用户表外键。

访问与订单覆盖 2012-03-19 至 2015-03-19，退款记录延续至 2015-04-01。主趋势采用 2012-04 至 2015-02 共 35 个可比月份，保留首尾两个边界月但不将其作为整月直接比较。完整年度同比使用 2013 与 2014；2015 年只做已有同期比较。

## 2. 核心业务发现

### 2.1 2014 年增长同时伴随访问规模与单位访问收入提高

| 指标 | 2013 年 | 2014 年 | 变化 |
| --- | ---: | ---: | ---: |
| 会话数 | 112,781 | 233,422 | +106.97% |
| 订单数 | 7,447 | 16,860 | +126.40% |
| 销售额（美元） | 393,247.87 | 1,075,612.19 | +173.52% |
| 会话转化率 | 6.60% | 7.22% | +0.62 个百分点 |
| 客单价（美元） | 52.81 | 63.80 | +20.81% |
| 每次访问收入（美元） | 3.49 | 4.61 | +32.15% |

销售增长伴随流量与单位访问收入同时提高。渠道分析进一步发现，gsearch_nonbrand 贡献年度会话收入增量的 51.95%，是规模增长的重要来源；没有广告成本，因此不能将其解释为投放回报最优。

### 2.2 移动端差异集中体现于多个路径阶段

2014 年桌面会话转化率为 9.18%，移动端为 3.31%。在有序漏斗中，桌面从商品列表进入详情的推进率为 88.12%，移动端为 69.72%，相差 18.40 个百分点；配送与支付等后段也有差异。

这一结果支持优先检查移动端商品列表入口、商品展示、表单与支付流程，但不能直接认定页面存在故障。不同阶段的分母不同，不能将阶段百分点差值相加，作为整体转化差距的解释。

### 2.3 2014 年 12 月销售额创新高，单位访问收入却下降

2014-12 销售额为 144,823.02 美元，比 11 月增长 13.00%；会话数增长 18.30%，每次访问收入反而下降 4.48%。按渠道与设备对称分解，每次访问收入变化约 -0.2284 美元，其中结构项 +0.0210、组内项 -0.2494 美元。负向变化主要出现在相同渠道设备组的内部表现。

进一步分析发现，支付至确认推进率从 65.49% 降至 63.05%，下降 2.44 个百分点；客单价从 64.57 美元降至 62.59 美元，多商品订单占比从 36.12% 降至 33.88%。因此后段流程与商品篮子都值得追查。漏斗按会话月、商品按订单月归属，不能将这些变化直接拼接成精确的因果贡献。

### 2.4 客单价增长主要对应每单件数增加

2013 至 2014 年，每单件数由 1.0223 增至 1.3393，平均单件成交价从 51.65 美元降至 47.63 美元。按“客单价 = 每单件数 × 平均单件成交价”进行对称恒等分解，客单价增加 10.99 美元，件数项 +15.74 美元，平均价格与商品结构项 -4.75 美元。

2014 年 Mini bear 的 95.71% 明细为非主商品；Original Mr. Fuzzy 与 Mini bear 同时出现于 2,426 笔订单，占全年订单 14.39%。这些现象可为附购与组合展示测试提供依据，但未证明推荐策略的增量效果。商品对占比使用全部订单作分母，不是条件附购率或提升度。

### 2.5 退款比较需要统一观察窗口

全观测期已记录退款 85,338.69 美元。以最后一次已观测退款时间作为截止代理，38,455 条商品明细具备完整 30 天年龄，其中 1,681 条在窗口内出现正金额退款，退款明细率为 4.37%；另外 1,570 条观察不足，同时从窗口分子与分母排除。

2014 年 Panda、Original、Forever Love、Mini 四款商品的 30 天退款明细率分别为 5.95%、5.31%、2.27%、1.33%。可优先补充前两款的退款原因和批次信息。截止代理不能证明此前每天均完整采集，退款率差异也未控制季节、渠道及客户构成，不能直接判定商品质量原因。

## 4. 步骤 01：明确问题与整理数据来源

围绕经营增长、渠道、设备路径、订单篮子和退款确定分析问题。读取六表、36 个字段的数据字典，建立会话、订单、商品明细、退款之间的关系，先明确各表粒度再设计查询。

| 文件或目录 | 内容及用途 |
| --- | --- |
| `assets/data_source.md` | 公开数据下载地址、文件放置方法及数据使用说明。 |
| `assets/data_dictionary.csv` | 六表字段、含义与关联的原始说明。 |
| `assets/raw_data/`（下载后创建） | 本地保存六份原始业务 CSV，保持原值，不提交到 GitHub。 |
| `README.md` | 项目目标、阅读入口、任务状态、验证摘要和复现导航。 |

阶段结果：采用 MySQL 处理关系查询，Python 完成检查、计算与导出，Excel 展示业务结果。原始数据保留在分析环境，仓库通过下载说明与字段字典记录输入来源。

| `env/requirements_lock.txt` | 已验证环境的完整依赖版本。 |
| `env/environment_notes.md` | 环境隔离约定与 Windows 文件包状态。 |
| `docs/environment_setup.md` | 环境参考、数据库连接参数与复现命令。 |
| `src/check_environment.py` | 下载数据后检查项目环境、依赖和六份 CSV，不登录数据库。 |

阶段结果：WSL 环境已支持本项目分析。Windows 仓库只保存清单和说明，未配置 Windows Python 或 MySQL。虚拟环境、系统工具和下载缓存不进入仓库。

## 6. 步骤 03：建库、建表并导入数据

通过 SQLTools 建立连接。数据库与表结构分别准备为 SQL 文件，六张表放在同一个建表文件中。金额使用 DECIMAL，建立可验证的主外键关系，营销字段允许为空。

导入时先处理父表，再处理子表；CSV 分块读取，空串、NULL 与反斜杠 N 按缺失值处理，金额以字符串传入 DECIMAL。六表写入放入同一事务，完成后逐表核对 CSV 与数据库行数。

| 文件 | 内容及用途 |
| --- | --- |
| `src/initialize_database.sql` | 创建项目数据库，查看数据库定义。 |
| `src/create_tables.sql` | 一次定义全部六表的字段、主键及外键。 |
| `src/import_data.py` | 分块读取 CSV 并事务式导入。 |
| `output/import_summary.json` | 六表 CSV/数据库行数对照，每表 rows_match 均为 true。 |

阶段结果：六表成功导入，共 1,735,068 行。行数一致证明本轮数量对齐，不等同于对所有字段逐行逐值完成了比对。导入脚本采用追加写入，已经导入的库不需为查看报告而再次执行导入。

## 7. 步骤 04：数据质量检查与指标定义

质量检查覆盖主键、外键和孤立记录、时间顺序、标志值、订单与明细的数量和金额、主商品一致性、退款归属及退款上限。这一步用于确认后续的关联与比率计算有可靠基础。

检查发现 utm_source、utm_campaign、utm_content 各缺失 83,328 条，39,917 次会话缺少来源网址。这些是字段分别统计的缺失数，不凭边际数量相等就认定是同一批会话。缺失可能来自未标记、自然或直接访问，不能自动作为错误删除。首尾月份和退款延迟也作为后续口径处理事项保留。

| 文件 | 内容及用途 |
| --- | --- |
| `src/check_data_quality.py` | 执行关系与业务一致性检查。 |
| `output/data_quality_report.json` | 45 项通过、0 项失败、0 项待确认，以及表行数、时间范围与营销缺失情况。 |
| `docs/metric_definitions.md` | 销售额、转化率、客单价、会话收入、时间归属及后续扩展口径。 |

阶段结果：当前规则未发现必须修复的错误，因此没有虚构去重删除、异常值清洗等操作；实际完成的是质量验证和分析口径处理。所有业务比率使用汇总分子除以汇总分母，避免简单平均各月或各组百分比。

## 8. 步骤 05：月度经营分析

先建立经营基准：按月统计访问、转化会话、订单、销售额、成本、转化率、客单价和每次访问收入。订单指标按下单月，会话指标按会话开始月；先将订单汇总到会话粒度，再关联会话，避免多订单放大会话数。

月份补齐后保留 37 个月度记录，其中 35 个可比月。只在相邻可比月间计算环比；年度比较采用完整年度，月份长短影响通过日均量另行检查。实际发现 6 笔订单跨越会话月与订单月，说明两种归属必须分开。

| 文件 | 内容及用途 |
| --- | --- |
| `src/monthly_overview.sql` | 按两种时间归属提取月度基础数量与金额。 |
| `src/monthly_overview.py` | 计算指标与环比，逐项对账并导出结果。 |
| `output/monthly_overview.csv` | 全部 37 个月，包含边界月标签。 |
| `output/monthly_overview_comparable.csv` | 35 个可比月，供主趋势与 Excel 使用。 |
| `output/monthly_overview_report.json` | 运行状态、126 项核对、范围、指标总量及月度明细。 |
| `src/review_monthly_results.py` | 离线核对 JSON/CSV，计算年度、同期及日均比较。 |
| `output/monthly_findings.json` | 派生比较和源指纹，供追溯结论。 |
| `tests/test_monthly_overview.py` | 7 项离线测试，覆盖时间归属、加权比率与边界等问题。 |

阶段结果：126 项核对通过，两份 CSV 全字段与 JSON 一致。定位了 2014 年增长、2014-12 总量与效率背离，以及 2015-02 月销售额下降但日均上升等问题，为渠道和路径分析确定重点。

## 9. 步骤 06：渠道与设备分析

保留原始 UTM、来源网址与设备维度，根据明确规则分类。已标记的搜索品牌/非品牌流量分别统计；未标记来源使用 direct_candidate、organic 候选等名称，保留判断限制。

在同一会话月份口径下，比较渠道规模、转化率和每次访问收入，并对变化作对称分解：区分流量结构变化与相同分组内部表现变化。进入或退出分组采用文档中的会计分配约定，不解释为因果。

| `output/channel_audit.csv` | 复现生成：517 条原始维度及分类审计，本地核对用，不提交仓库。 |

## 10. 步骤 07：有序购买漏斗

在每次会话内部，按浏览时间和页面浏览编号排序，逐级寻找有效的后续事件。重复浏览只计一次会话；合并四种商品详情页及两个支付页版本，保留原始页面清单。

同时记录有序路径、原始页面到达和实际订单。这样不会把到过后续页面但顺序不符的会话误记为完整路径，也不会仅用确认页代替订单。推进率用同一分组的前一有效阶段作分母。

| 文件 | 内容及用途 |
| --- | --- |
| `src/funnel_analysis.sql` | 在会话内建立明确事件顺序并计算各阶段。 |
| `src/funnel_analysis.py` | 路径和订单对照、阶段率、设备/渠道/落地页汇总与比较。 |
| `output/funnel_audit.csv` | 复现生成：549 条路径审计，本地核对用，不提交仓库。 |
| `output/funnel_page_inventory.csv` | 16 个页面 URL 及映射依据。 |
| `output/funnel_groups.csv` | 211 条分组总量、路径覆盖和订单对照。 |
| `output/funnel_stages.csv` | 1,688 条分组阶段人数与推进率。 |
| `output/funnel_comparisons.csv` | 560 条期间阶段变化。 |
| `output/funnel_analysis_report.json` | 151 项核心核对、附加检查、基准指纹和待解释记录。 |
| `src/review_funnel_results.py` | 从审计重算分组、阶段和比较，核对派生文件。 |
| `output/funnel_findings.json` | 设备阶段差异、12 月变化及源指纹。 |
| `docs/funnel_methodology.md` | 页面映射、路径顺序、阶段分母及异常处理。 |
| `tests/test_funnel_analysis.py` | 10 项测试，包含实际 SQL 小型样例、乱序与重复页面等情况。 |

阶段结果：151 项核心核对及附加检查通过，四份派生 CSV 全字段一致；本数据下有序确认会话与实际转化会话均为 32,313，未出现当前规则下待解释的路径不一致。定位了移动端列表至详情差异和 12 月支付至确认回落。

## 11. 步骤 08：商品、订单篮子与退款

商品销售保持一行一条订单明细；退款单独读取后归集到明细，支持同一明细多次部分退款而不放大销售额。订单篮子先汇总明细再关联订单金额；商品对先在订单内去重，再按无序对计数。

退款同时保留累计观测口径与统一 30 天窗口。仅将已达到完整窗口年龄的明细放入可比窗口分母，分子也只取这些明细在窗口内发生的正金额退款。第 30 天同一时刻的退款包括在内，观察不足另列。

| 文件 | 内容及用途 |

## 12. 步骤 09：制作 Excel 经营看板

从已复核结果生成四个展示页：经营总览、渠道设备、购买漏斗、商品退款。四张输入页按月、月/渠道/设备、月/路径维度、月/商品保留汇总数据，避免把百万行浏览明细装入工作簿。图表坐标轴、图例和显示布局已整理。

经营总览 B4/E4 是统一的起止月份选择，其他视图引用同一期间。比率使用所选期间的合计分子除以合计分母。总览长期趋势展示全部 35 个可比月份。

## 15. 阅读与复现路径

先阅读本报告并打开最终看板，再查阅指标及三份方法文档。追查数值时，按“发现 JSON—分析报告 JSON—汇总 CSV—SQL/Python”定位；需要逐条复核时，下载原始数据并重新生成审计文件。

## 16. 数据解释与验证边界

销售额单位为美元，默认未扣退款；每次访问收入使用会话归属收入，客单价使用订单归属销售额。数据时间未提供时区，因此保留原始事件时间；过程记录采用 Asia/Shanghai。排除首尾月是可比分析约定，不等于证明每个中间自然日都采集完整。

退款截止代理为 2015-04-01 18:11:08，统一窗口改善观察年龄的可比性，不能保证数据源完整或退款原因可比。商品上市时间不同，新品的低基数增幅应结合上市时长阅读。

本项目完成历史数据的描述分析和可复现文件整理。原生 Excel 全月份交互、业务建议的实验验证、数据库索引实测与备份恢复演练均不计入已验证成果。
